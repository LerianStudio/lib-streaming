# AGENTS

This file provides repository-specific guidance for coding agents working on `lib-streaming`. `CLAUDE.md` is a symlink to this file — single source of truth.

## Project snapshot

- Module: `github.com/LerianStudio/lib-streaming/v3`
- Language: Go
- Go version: `1.26.3` (see `go.mod`)
- Current API version: 3.x (module path carries the `/v3` suffix — cut by the event-streaming contract redesign: one topic per producing application, strict `ce-source`, the app segment in `ce-type`, schema version out of the topic, underscores in route keys, and the app-stream consumer surface. Import paths are `github.com/LerianStudio/lib-streaming/v3/...`. See `CHANGELOG.md` for tagged history and the v2→v3 migration.)
- Layout: public root facade at the repository root (`package streaming`) with implementation in internal packages (`internal/contract`, `internal/config`, `internal/manifest`, `internal/cloudevents`, `internal/emitter`, `internal/producer`, `internal/transport`). Public test helpers live in `streamingtest`. Scaffolding (`docs/`, `.github/`, `scripts/`) stays in subdirectories.

## Primary objective for changes

- Treat the documented public API surface as the contract. Breaking changes MUST land with a `CHANGELOG.md` entry and a migration note.
- Prefer explicit error returns over panic paths in production code.
- Keep behavior nil-safe and concurrency-safe by default.

## API invariants to respect

### Streaming

- lib-streaming provides both event production (`streaming.NewBuilder()`) and at-least-once stream consumption (`streaming.NewConsumer()`); `github.com/LerianStudio/lib-commons/v6/commons/rabbitmq` handles internal command queues. The two are orthogonal and neither deprecates the other.
- Consumer surface: `streaming.NewConsumer().Brokers(...).Group(...).Source(...).Apps(...).OnFrom(app, "<resourceType>.<eventType>", fn).Build(ctx)` then `Run(ctx)`.
  - **`Source(...)` is REQUIRED** for an enabled consumer (`ErrConsumerMissingSource`), read from the same `STREAMING_CLOUDEVENTS_SOURCE` as the producer side — one service, one identity. It names the consumer's OWN DLQ topic.
  - `Apps(...)` subscribes by producing-application name (resolving to that app's one topic) AND arms source verification; `Topics(...)` is the raw escape hatch and composes with `Apps`.
  - **Dispatch is scoped by `(app, event key)`.** `OnFrom(app, key, fn)` names the producer; `On(key, fn)` is the single-app shorthand and binds to the sole app in scope. A bare `On` under SEVERAL apps FAILS the build (`ErrBareOnWithMultipleApps`), and `OnFrom` naming an app the consumer does not subscribe to FAILS (`ErrUnknownDispatchApp`). The app segment exists because two services publish byte-identical event names — `ce-type` carries the app for exactly this reason, and a source-blind dispatch key threw that away.
  - `Handler(...)` still takes the whole stream and rejects the genuinely dispatch-only knobs: `On`/`OnFrom` (`ErrHandlerAndDispatchBothSet`) and `UnmatchedPolicy` (`ErrHandlerAndUnmatchedPolicyBothSet`). `ExpectSources` is NOT one of them any more — see below.
  - **ce-source verification runs in the RUNTIME**, ahead of either handler mode, so a whole-stream `Handler(...)` gets it too (that mode needs it most — it sees every record on a shared-ACL topic). A foreign source quarantines with `ErrUnexpectedSource` / cause kind `source_mismatch`. `ErrHandlerAndExpectSourcesBothSet` is DELETED.
  - `ExpectSources(...)` REPLACES the `Apps`-derived allowlist, is validated entry-by-entry, and must cover every app in `Apps`; setting BOTH `Apps` and `Topics` without an explicit `ExpectSources` FAILS the build (`ErrAmbiguousSourceVerification`) rather than guessing — `STREAMING_CONSUMER_EXPECT_SOURCES` (csv) is the env equivalent and the only way to resolve that refusal from the environment; a fluent `ExpectSources(...)` overrides it, and error texts name whichever origin the list came from.
  - `ErrUnhandledEvent` and `ErrUnexpectedSource` are synthesized BY the library and quarantine outright — they are NEVER offered to the service `Classifier`. They are structural and can never become satisfiable by waiting; routing them through a "retry anything I don't own" classifier wedged the partition forever.
  - Unmatched events are IGNORED (skipped + committed) by default — `UnmatchedPolicy(UnmatchedError)` quarantines them. They are metered on `streaming_consumer_unmatched_total` (labelled by event key, capped at 64 distinct values with the overflow folded into `other` and one WARN at the boundary) and logged once per key; ABOVE the cap each newly-seen key is still LOGGED BY NAME, globally rate-limited to one line per 30s.
  - `Healthy(ctx)` fails with `ErrConsumerPartitionHalted` once a partition has been halted across 3 consecutive poll cycles, naming topic/partition/cause. Polling cleanly is not progress: a fail-closed DLQ outage or a stuck downstream kept `Healthy` green forever.
  - The library owns commit, retry, seek-back, DLQ, tenant propagation, and rebalance safety; a consuming service implements only `streaming.Handler`. `.Enabled(false)` yields a disabled-mode no-op (the consumer kill switch). The `STREAMING_CONSUMER_*` env surface is read by `streaming.LoadConsumerConfig()` and adopted with `NewConsumer().FromConfig(cfg)` — without `FromConfig` none of those variables is read by anything. There is **no DLQ-suffix knob**: a consumer quarantines into its OWN `lerian.streaming.<Source>.dlq`.
  - `x-lerian-dlq-error-message` carries the handler's error string with ONLY broker credentials stripped (and capped at 4 KiB), so **handlers must not embed PII in returned errors** — it lands on the DLQ topic verbatim. See `docs/design/consumer.md`.
- Three-method `Emitter` interface (`Emit(ctx, EmitRequest) error`, `Close() error`, `Healthy(ctx) error`). Three implementations: root `*Producer` (facade over the multi-target internal producer), `NoopEmitter` (fail-safe for disabled feature flags), and `streamingtest.MockEmitter` (concurrency-safe test double with deep-copy via `Requests()`, `AssertEventEmitted/AssertEventCount/AssertTenantID/AssertNoEvents` helpers, and `WaitForEvent`).
- Producer construction: `streaming.NewBuilder()` is the public producer entry point. The Builder validates the route table, constructs per-target transport adapters, and returns `streaming.Emitter`. Disabled-feature-flag environments use `streaming.NewNoopEmitter()` instead. `LoadConfig() (Config, []string, error)` reads every `STREAMING_*` env var, applies defaults, returns warnings, and validates the result; validation is skipped when `Enabled=false`. The transport-security env vars are `STREAMING_TLS_ENABLED`, `STREAMING_TLS_CA_CERT` (base64 PEM CA), `STREAMING_SASL_MECHANISM` (PLAIN / SCRAM-SHA-256 / SCRAM-SHA-512), `STREAMING_SASL_USERNAME`, `STREAMING_SASL_PASSWORD` (secret; never logged), and `STREAMING_SASL_ALLOW_PLAINTEXT` (canonical). `STREAMING_ALLOW_PLAINTEXT_SASL` is a DEPRECATED alias consulted only when the canonical var is unset — the canonical value wins when both are set and the alias appends a deprecation warning to the returned warnings slice. All are default-off, so existing deployments are unchanged.
- Builder hard requirements at `Build(ctx)`: a non-empty `Source(...)` (CloudEvents `ce-source`; emits `ErrMissingSource` when empty), a non-empty `Catalog(...)`, a non-empty `Routes(...)` table, and at least one `Target(...)` whose `Kind` matches every route resolving to it. Missing Source / catalog / target each surfaces as a distinct caller-correctable sentinel — no inferred defaults.
- Builder setters (chained, return `*Builder`): `Source`, `Catalog`, `Routes`, `Target`, `TargetExtra`, `RegisterTransport`, `OutboxWriter`, `OutboxRepository`, `Options`, `PartitionKey`, `TLSConfig`, `SASL`, `AllowPlaintextSASL`, `Logger`, `MetricsFactory`, `Tracer`, `CircuitBreakerManager`, `AllowSystemEvents`, `CloseTimeout`, `CBFailureRatio`, `CBMinRequests`, `CBTimeout`, `TLSFromConfig`, `SASLFromConfig`, plus the convenience target helpers `SQSTarget` / `RabbitMQTarget` / `EventBridgeTarget`. `TLSFromConfig(cfg)` / `SASLFromConfig(cfg)` derive the broker TLS dial and SASL mechanism from a loaded `Config` (the `STREAMING_TLS_*` / `STREAMING_SASL_*` env vars) and are no-ops when the corresponding feature is disabled; a malformed CA or invalid mechanism is captured as a deferred build error that `Build` surfaces (first error wins) as `ErrInvalidTLSConfig` / `ErrInvalidSASLMechanism`.
- Builder CB tuning setters: `CBFailureRatio(float64)`, `CBMinRequests(int)`, `CBTimeout(time.Duration)`. Zero values fall back to the lib-commons HTTP preset (`0.5` / `10` / `30s`). The `CBTimeout` value is also what feeds the CB recovery goroutine's tick interval (`clamped(cbTimeout/4, [500ms, 5s])`); shortening `CBTimeout` tightens the bounded recovery envelope.
- `Builder.Logger(...)` persists the resolved logger directly on the Builder struct AND appends `WithLogger(...)` to extraOptions. The persisted logger flows into `TransportAdapterOptions.Logger` for every per-target factory call so SQS / RabbitMQ / EventBridge / custom adapters log against the caller's structured logger from construction onward. (Earlier behavior scanned extraOptions and always returned `log.NewNop()` because closure state cannot be portably inspected — that bug is fixed by direct persistence.)
- Functional options (passed via `Builder.Options(...)` or the equivalent dedicated Builder setters): `WithLogger`, `WithMetricsFactory`, `WithTracer`, `WithCircuitBreakerManager`, `WithPartitionKey`, `WithCloseTimeout`, `WithOutboxRepository`, `WithOutboxWriter`, `WithTLSConfig`, `WithSASL`, `WithAllowPlaintextSASL`, `WithAllowSystemEvents`, `WithCatalog`. Passing nil for any factory or manager is safe — the Producer falls back to a no-op recorder / its own CB manager. `WithOutboxRepository` and `WithOutboxWriter` are mutually exclusive (last call wins). SASL requires TLS by default; `WithAllowPlaintextSASL` is unsafe and local/dev only.
- Public type aliases at the root facade carry the transport port surface for custom adapters: `TransportAdapter` (the outbound port), `TransportMessage` (per-publish payload, deep-copied before adapters see it), `TransportHeader`, `TransportAdapterOptions` (factory input — name, brokers, logger, caller-typed `Extra`), `TransportAdapterFactory`, and `PartitionKeyFunc`. `EmitterOption`, `OutboxWriter`, and the manifest / catalog / policy / route / health types are also exposed via aliases — services depend on the root package exclusively, never on `internal/...`.
- `*Producer` carries one method beyond the Emitter contract that callers may need: `Descriptor(base PublisherDescriptor) (PublisherDescriptor, error)`. It returns the validated descriptor with the per-process `ProducerID` populated AND `Source` OVERWRITTEN with the producer's own `ce-source` — the manifest's document-level topic derives from that field, so the running producer is its only authority; a caller-supplied Source is discarded. Suitable for feeding `BuildManifest` or stamping into custom DLQ surface metadata. `RegisterOutboxRelay(*outbox.HandlerRegistry) error`, `Run`, `RunContext`, `Close`, and `CloseContext` complete the lifecycle surface.
- `Event` struct carries the CloudEvents 1.0 binary-mode envelope: `TenantID`, `ResourceType`, `EventType`, `EventID`, `SchemaVersion`, `Timestamp`, `Source` (required CloudEvents fields) plus `Subject`, `DataContentType`, `DataSchema`, `SystemEvent`, and `Payload json.RawMessage`. `ApplyDefaults()` fills missing EventID (UUIDv7 via `commons.GenerateUUIDv7`), Timestamp (now UTC), SchemaVersion ("1.0.0"), and DataContentType ("application/json") on a local copy before publish.
- **ONE topic per producing application.** `Event.Topic()` returns `"lerian.streaming." + Source` and nothing else — no resource type, no event type, no schema-version suffix, ever. All traffic rides it: business facts and service-to-service commands alike. DLQ is `"lerian.streaming." + Source + ".dlq"` (`AppTopic(source) (string, error)` / `AppDLQTopic(source) (string, error)`, exported at the root — both VALIDATE the source and return `ErrMissingSource`/`ErrInvalidSource` rather than deriving a name from garbage). **Kafka ACLs: every application WRITES exactly those two names** — its topic and its `.dlq` — whether it produces, consumes, or both, because a consumer quarantines into its OWN DLQ rather than the producer's; it READS the topics of the applications it consumes. `Event.PartitionKey()` resolves through a fallback chain: `"system:" + EventType` when `SystemEvent=true`, else `TenantID`, else `Subject` (the aggregate id), else `EventID`. The Subject/EventID rungs exist because franz-go's sticky-key partitioner branches on `key != nil` and `[]byte("")` is not nil — an empty key would hash to one constant partition and pin an entire single-tenant application stream to it. **The key guarantees partition AFFINITY; whether that becomes ORDER depends on the path**: direct emit gives per-tenant FIFO, but an OUTBOX-RELAYED emit gives affinity only — the lib-commons relay drains rows with per-event retry and no per-aggregate serialization, so a failed row republishes AFTER a later row of the same tenant. Services that emit exclusively through the outbox get affinity and nothing more; a consumer needing strict per-aggregate order must reconcile on its own sequence/version field. A `WithPartitionKey` override that returns `""` falls back to `Event.PartitionKey()` at every publish path — an empty override key would reintroduce exactly the one-partition collapse the fallback chain exists to prevent.
- **`Source` is strict.** A source must match `^[a-z0-9][a-z0-9_-]*$` — one dot-free lowercase segment — and be ≤228 bytes so the derived DLQ topic fits Kafka's 249-byte limit (249 − len(`lerian.streaming.`) − len(`.dlq`)). `contract.ValidateSource` (root: `streaming.ValidateSource`) is applied at `LoadConfig`, `Builder.Build`, `NewPublisherDescriptor`, and producer preflight. v3 REJECTS an invalid source with `ErrInvalidSource`; it never rewrites one. The v2 lossy `sanitizeSourceSegment` is DELETED, and with it the risk of two distinct services folding onto one topic namespace and ACL scope. The old `//lerian.midaz/<svc>` URI shape is dead.
- **`ce-type` carries the app segment**: `"studio.lerian." + Source + "." + ResourceType + "." + EventType`. v2's source-blind form let two services emit byte-identical `ce-type` values for same-named events — a homonym collision a consumer reading only `ce-type` could not detect. Every other `ce-*` header is unchanged (binary content mode; `ce-tenantid`, `ce-resourcetype`, `ce-eventtype`, `ce-schemaversion`, `ce-systemevent` extensions).
- **Schema version left the topic.** `ce-schemaversion` is the only version carrier on the wire; semver is still validated at `NewEventDefinition` time. There is no `EventDefinition.Topic(source)` — a definition has no topic of its own. `EventDefinition.EventKey()` returns the `"<resourceType>.<eventType>"` dispatch selector that replaced it.
- Caller-correctable sentinels (synchronous, no I/O — `IsCallerError(err)` returns true): `ErrMissingSource`, `ErrMissingResourceType`, `ErrMissingEventType`, `ErrSystemEventsNotAllowed`, `ErrInvalidTenantID`, `ErrInvalidResourceType`, `ErrInvalidEventType`, `ErrInvalidSource`, `ErrInvalidSubject`, `ErrInvalidEventID`, `ErrInvalidSchemaVersion`, `ErrInvalidDataContentType`, `ErrInvalidDataSchema`, `ErrPayloadTooLarge` (1 MiB cap for Kafka, 256 KiB for SQS/EventBridge), `ErrNotJSON`, `ErrEventDisabled`, `ErrInvalidEventDefinition`, `ErrInvalidOutboxEnvelope`, `ErrDuplicateEventDefinition`, `ErrUnknownEventDefinition`, `ErrInvalidDeliveryPolicy`, `ErrInvalidPublisherDescriptor`, `ErrInvalidRouteDefinition`, `ErrInvalidDestination`, `ErrDuplicateRouteDefinition`, `ErrNoRoutesConfigured`, `ErrNoRequiredRoute`, `ErrMissingTarget`, `ErrMultiTransportRuntimeNotConfigured`, `ErrInvalidTLSConfig`, `ErrPlaintextSASLNotAllowed`, `ErrInvalidSASLMechanism`.
- Config-validation sentinels (also caller-correctable), **named for the side they belong to**: producer — `ErrProducerMissingBrokers`, `ErrProducerInvalidConfigField`, `ErrInvalidCompression`, `ErrInvalidAcks`, `ErrInvalidSASLMechanism`; consumer — `ErrConsumerMissingBrokers`, `ErrConsumerMissingGroup`, `ErrConsumerMissingTopics`, `ErrConsumerMissingSource`, `ErrConsumerInvalidConfigField`, `ErrNilHandler`, `ErrHandlerAndDispatchBothSet`, `ErrHandlerAndUnmatchedPolicyBothSet`, `ErrBareOnWithMultipleApps`, `ErrUnknownDispatchApp`, `ErrAmbiguousSourceVerification`, `ErrExpectSourcesMissingApp`, `ErrInvalidExpectSource`. There is deliberately no bare `ErrMissingBrokers` / `ErrInvalidConfigField` any more: the two sides define DIFFERENT error values under the same name, so one bare alias silently returned false for every `errors.Is` against the other side's Build failure.
- Consumer RUNTIME sentinels (not config): `ErrUnexpectedSource` (ce-source outside the allowlist — quarantined before any handler runs, in both handler modes), `ErrUnhandledEvent` (no handler for the `(app, event key)` pair, under `UnmatchedError`), `ErrConsumerPartitionHalted` (returned by `Healthy`, not per record). The library synthesizes the first two, so both bypass the service `Classifier`.
- Lifecycle/wiring sentinels (NOT caller errors — `IsCallerError` returns false): `ErrEmitterClosed`, `ErrNilProducer`, `ErrCircuitOpen`, `ErrOutboxNotConfigured`, `ErrOutboxTxUnsupported`, `ErrNilOutboxRegistry`.
- `*EmitError` carries `ResourceType`, `EventType`, `TenantID`, `Topic`, `Class ErrorClass`, and `Cause error`. `Error()` runs through `sanitizeBrokerURL` so SASL credentials never surface in logs. `IsCallerError(err)` returns true for the caller-correctable sentinels and for `*EmitError` with class `ClassSerialization`, `ClassValidation`, or `ClassAuth`.
- `*MultiEmitError` aggregates per-route failures from a single multi-target Emit. `Required` and `Optional` slices each carry one `RouteError{RouteKey, Target, Cause}` per failed route. `Unwrap()` returns `errors.Join(...)` over every Required `Cause` so `errors.Is(multiErr, ErrCircuitOpen)` matches when ANY required route was circuit-open and `errors.As(multiErr, &emitErr)` captures the FIRST `*EmitError` in the chain. `IsCallerError(*MultiEmitError)` returns true only when EVERY Required failure is itself caller-correctable — a single infrastructure-class failure flips the aggregate to non-caller. Optional routes never trigger surfacing.
- Eight `ErrorClass` values: `ClassSerialization`, `ClassValidation`, `ClassAuth`, `ClassTopicNotFound`, `ClassBrokerUnavailable`, `ClassNetworkTimeout`, `ClassContextCanceled`, `ClassBrokerOverloaded`. DLQ routing applies to every class except `ClassValidation` and `ClassContextCanceled` (TRD §C9), gated AND'd with the per-event `DeliveryPolicy.DLQ` mode.
- Lifecycle invariants: `*Producer` implements `commons.App` — `Run(launcher)` / `RunContext(ctx, launcher)` block until ctx is canceled or Close is called, then invoke `CloseContext` with a fresh background ctx so a canceled caller ctx does not abort Flush. `Close`/`CloseContext` are idempotent via `atomic.Bool` CAS. Post-close `Emit` returns `ErrEmitterClosed` synchronously before any I/O. Service methods MUST NOT call Close — the Launcher owns lifecycle.
- Background CB recovery goroutine: each `*Producer` spawns ONE additional goroutine via `runtime.SafeGoWithContextAndComponent` (component=`"streaming"`, goroutine_name=`"cb_recovery_loop"` — static label for bounded panic-metric cardinality). It ticks at `clamped(cbTimeout/4, [500ms, 5s])`. With lib-commons `TenantAwareManager`, it calls `manager.GetState` on every no-tenant target breaker and `GetStateForTenant` on the Producer-owned `(tenant, target)` breaker keys recorded during Emit; otherwise it calls `manager.GetState` on every registered target. This makes gobreaker's lazy OPEN→HALF-OPEN expiry transition fire deterministically — without this loop, an emit-only service whose breaker has tripped OPEN could stay degraded forever. Lifecycle: started at the tail of `NewProducerMulti` after listener registration; exits when `Close`/`CloseContext` closes `p.stop`. Per-Producer cost: one goroutine, microsecond-scale per tick across its own targets and tenant breaker keys; it does not scan unrelated manager inventory. Interval is intentionally not directly customizable; the CBTimeout-derived envelope is the public contract. `Healthy(ctx)` degrades when the loop is dead or stale. Panic policy is `runtime.KeepRunning` — the wrapped goroutine exits on panic with full trident recording, no auto-restart (a panicking `GetState`/`GetStateForTenant` is a real bug, not noise to swallow).

- **Two schema majors may share ONE event key, deliberately.** A catalog may hold two definitions with the same `(ResourceType, EventType)` and different `SchemaVersion` majors: their catalog `Key`s differ, but `EventKey()` — `"<resourceType>.<eventType>"` — is identical, because in v3 the schema version left both the topic and the dispatch selector and lives only in `ce-schemaversion`. That is how a producer ships v1 and v2 of the same fact through a migration window without minting a second event name consumers must learn and later unlearn. **Consumer consequence, mandatory:** one `On(...)` handler receives BOTH majors, so a handler for an event key with multiple majors in flight MUST branch on `Event.SchemaVersion` before touching the payload — a v2 payload parsed as v1 is silent data corruption, not a decode error.

### Multi-transport routing (Builder)

- `streaming.NewBuilder()` is the public producer construction entry point (`streaming.NewConsumer()` constructs the at-least-once group consumer). A single Emit fans out across N routes in deterministic route-table order.
- A `RouteDefinition` maps catalog definitions to one `(Target, Destination)` pair. `DefinitionKey` is OPTIONAL: empty means CATCH-ALL, serving every definition in the catalog. Many routes per definition are allowed; each one is evaluated independently per Emit.
- Route resolution is **ADDITIVE PER TARGET**, computed once at `NewRouteTable` time. A definition resolves to its definition-scoped routes PLUS every catch-all route whose `Target` no scoped route already claims. Scoping the SAME target overrides the catch-all for that target alone (re-point a handful of events at another topic, no double-publish); scoping a DIFFERENT target ADDS (shadow those events to SQS, and they still ride the app topic). Winner-take-all was the v3-draft rule and is DELETED — it silently diverted an event off the app topic whenever a shadow route existed, which is durable loss reported as a successful Emit.
- Two catch-all routes (both with an empty `DefinitionKey`) on different targets mean **app-wide mirroring**: the entire stream is published twice. That is the only way to express "everything, twice", and it is deliberate — pinned by `TestRouteTable_SecondCatchAllMirrorsEveryDefinition`.
- `validateRoutesAgainstTargets` FAILS construction with `ErrNoRequiredRoute` when any catalog definition resolves to routes but none of them is `RouteRequired`. A definition served only by optional routes can lose every copy while `Emit` returns nil; durability must be provable at build time. A definition with NO routes at all keeps `ErrNoRoutesConfigured` — different bug, different name.
- `NewRouteTable` rejects two routes sharing one `(DefinitionKey, Target)` pair (`ErrDuplicateRouteDefinition`), catch-alls included. Resolution buckets by definition and the Emit fan-out publishes every route in the bucket, so such a pair delivered the same event twice to one destination while `Emit` returned nil. `MergeRouteOverrides` resolves override-vs-base precedence by that same pair but never compares base routes against each other.
- The single-Kafka `NewProducer` convenience path synthesizes exactly ONE catch-all route to the app topic on the `"primary"` target. v2's route-per-catalog-entry fanout (`kafkaRoutesForCatalog`) is DELETED — under topic collapse it produced N rows with one identical destination. The multi-target Builder and explicit `KafkaTopic(...)` destinations are unchanged.
- Route keys allow underscores inside each dot-delimited segment: `^[a-z0-9][a-z0-9_-]*(\.[a-z0-9][a-z0-9_-]*)+$`. v2 forbade them, which forced every consuming repo to carry `_`→`-` translation machinery because ResourceTypes are snake_case; the producer's `canonicalRouteKey` translator is gone with it.
- `RouteRequirement` is `RouteRequired` (must succeed for the Emit to succeed; failures aggregate in `*MultiEmitError`) or `RouteOptional` (best-effort; metrics + DLQ only).
- `TransportKind` is one of `TransportKafkaLike`, `TransportSQS`, `TransportRabbitMQ`, `TransportEventBridge`, `TransportCustom`. Every route's `Destination.Kind` must match its target's adapter `Kind`; `NewProducerMulti` rejects mismatches at construction.
- Target names are validated at `Build`: empty names, names containing control characters, names exceeding `MaxEventIDBytes` (256), and names matching credential-like patterns are rejected. The cap matches the per-event ID cap so the validation surface is symmetric across routes and targets. The CB recovery goroutine drives state transitions on every registered target and surfaces `target.Name` into operator logs via the per-target `StateChangeListener`, so a target name carrying a newline or other control character would inject crafted lines into the log stream — the validation closes that vector.
- The Producer runtime registers one no-tenant compatibility breaker per target with service name `streaming.producer:<producerID>:target:<targetName>`. When the manager satisfies lib-commons `TenantAwareManager`, non-system events lazily register tenant-scoped breakers for the same service name keyed by `Event.TenantID` (or a stable safe surrogate when the Event tenant ID is outside tenant-manager's ASCII shape). `targetRuntime.state` tracks only the no-tenant breaker; tenant-scoped state is read from the manager and observed through lib-commons `tenant_hash` CB metrics/logs. `streaming_circuit_state` is a single-dimension gauge tracking the primary target's no-tenant breaker only.
- Outbox: when a route's breaker is OPEN and an `OutboxWriter` is wired, `OutboxEnvelope` (versioned) persists target name, transport kind, route key, destination, and policy alongside the event. Replays route through the same target adapter and bypass the breaker so a sustained outage cannot re-enqueue itself.
- DLQ: each `RouteDefinition` may declare its own DLQ destination; routing rules apply per route (every error class except `ClassValidation` and `ClassContextCanceled`, AND-gated with the resolved policy).
- Built-in non-Kafka adapters under `internal/transport/{sqs,rabbitmq,eventbridge}` MUST NOT depend on aws-sdk-go-v2 or amqp091-go. Each exposes a small caller-supplied client interface (`SQSPublisherClient`, `RabbitMQPublisher`, `EventBridgePutEventsClient`); callers MUST implement `Ping(ctx) error` on production clients because adapter health fails closed when the client has no health affordance.
- **SQS routes resolve DNS at construction.** `NewRouteDefinition` and `NewRouteTable` validate every SQS `Destination` against AWS SQS endpoint host patterns, then call `ssrf.ResolveAndValidate` to reject DNS answers in blocked ranges (loopback, link-local, RFC1918, cloud-metadata ranges). Validation uses a bounded internal retry envelope (3 attempts, 500ms each, 25ms backoff) to tolerate brief resolver jitter while still failing startup closed. This prevents caller-owned SDK wrappers from signing requests to arbitrary public hosts and fails startup when an SQS hostname resolves unsafely. Operational consequence: service bootstrap blocks on the resolver for each unique SQS queue URL in a route table, and a DNS outage at boot causes `NewRouteTable` (and therefore `Builder.Build`) to return an error and fail startup. There is no public timeout knob — by design, this is a one-time cost paid at startup, not per-Emit. Deploy with a healthy DNS resolver in the pod/container network namespace.
- Public root constructors: `streaming.SQSAdapter`, `streaming.RabbitMQAdapter`, `streaming.EventBridgeAdapter` (return `TransportAdapter`); Builder helpers: `Builder.SQSTarget`, `Builder.RabbitMQTarget`, `Builder.EventBridgeTarget` (register both target and factory in one call).
- RabbitMQ via the streaming Builder is **events-only** — past-tense business facts for third-party / SaaS subscribers. Internal command queues remain on `github.com/LerianStudio/lib-commons/v6/commons/rabbitmq`.
- For SDK shapes the library does not cover, use `TransportCustom` with `Builder.RegisterTransport(TransportCustom, factory)`. The factory receives a per-target `TransportAdapterOptions` carrying name, brokers, logger, and a caller-typed `Extra` payload.

### Catalog and Delivery Policy

- `Catalog` is an immutable, deterministically-ordered registry of `EventDefinition` records constructed via `NewCatalog(definitions ...EventDefinition)`. Rejects duplicate `Key` AND duplicate `(ResourceType, EventType, SchemaVersion)` contract tuples at construction. `Definitions()` returns a defensive copy.
- `EventDefinition` carries `Key`, `ResourceType`, `EventType`, `SchemaVersion`, `DataContentType`, `DataSchema`, `SystemEvent`, `Description`, and `DefaultPolicy DeliveryPolicy`. Validated + normalized by `NewEventDefinition`.
- `EmitRequest` is the catalog-keyed input to `Emit`: `DefinitionKey`, `TenantID`, `Subject`, `EventID`, `Timestamp`, `Payload json.RawMessage`, `PolicyOverride DeliveryPolicyOverride`. Public constructor `NewEmitRequest(EmitRequest) (EmitRequest, error)` validates request-local shape.
- `DeliveryPolicy` modes: `DirectMode` (`direct`, `skip`) × `OutboxMode` (`never`, `fallback_on_circuit_open`, `always`) × `DLQMode` (`never`, `on_routable_failure`) × `Enabled bool`. `DefaultDeliveryPolicy()` = `{Enabled:true, Direct:direct, Outbox:fallback_on_circuit_open, DLQ:on_routable_failure}`. Cross-field rule: `Direct=skip` requires `Outbox=always`.
- `ResolveDeliveryPolicy` precedence: definition default → config override (`Config.PolicyOverrides`) → call override (`EmitRequest.PolicyOverride`). Each override step validates independently.

### Outbox

- Outbox fallback: when an outbox writer is wired and a route's target circuit breaker is OPEN, Emit writes the event to the outbox and returns nil. The caller registers the replay handler via `(*Producer).RegisterOutboxRelay(registry *outbox.HandlerRegistry) error`, which dispatches each envelope through its originating target's adapter (NOT through Emit) so replays bypass the breaker and cannot re-enqueue themselves on a sustained outage. Without an outbox wired, circuit-open Emits return `ErrCircuitOpen`. The Producer NEVER constructs an `OutboxRepository` or `OutboxWriter` itself — ownership stays with the consuming service.
- `OutboxWriter` interface (one method: `Write(ctx, OutboxEnvelope) error`). Optional `TransactionalOutboxWriter` adds `WriteWithTx(ctx, *sql.Tx, OutboxEnvelope) error`. Ambient transaction is propagated via `WithOutboxTx(ctx, *sql.Tx)`. `WithOutboxRepository(repo outbox.OutboxRepository)` adapts the lib-commons repo via the internal `libCommonsOutboxWriter` (which implements both writer interfaces).
- Pool-per-tenant outbox dispatch (lib-commons `TenantPoolResolver` seam in `commons/outbox/postgres`, since lib-commons `v6`) is a lib-commons dispatcher concern and is transparent to lib-streaming. The write side joins the caller's ambient transaction (`WriteWithTx` via `WithOutboxTx`) and therefore already lands on the caller's tenant pool; the relay republishes from the persisted `OutboxEnvelope` — tenant identity travels in `Event.TenantID` inside the marshaled payload — regardless of which pool/schema the row was read from. Do NOT add a ctx-vs-envelope tenant cross-check in the relay: the persisted payload is authoritative and the lib-commons dispatcher already read the row from the correct per-tenant database, so the check buys nothing and risks false-mismatch aborts.
- `OutboxEnvelope` is the persisted route-aware shape: `Version`, `RouteKey`, `DefinitionKey`, `Target`, `Transport`, `Destination`, `AggregateID`, `Requirement`, `Policy`, `Event`. `Validate()` enforces structural integrity (canonical route key, valid transport, matching destination kind, valid policy, well-formed event); `ValidateShape()` is the cheaper trusted-persist variant that skips URL/SSRF re-validation. All outbox rows use the stable `EventType = "lerian.streaming.publish"` (`StreamingOutboxEventType`); per-route dispatch happens via the persisted `OutboxEnvelope.Target` lookup against the registered targets.
- DLQ: per-topic, named `"<destination topic>.dlq"` — for the default route that is `"lerian.streaming.<source>.dlq"`, i.e. one DLQ per application. Each DLQ message carries six headers (`x-lerian-dlq-source-topic`, `x-lerian-dlq-error-class`, `x-lerian-dlq-error-message`, `x-lerian-dlq-retry-count`, `x-lerian-dlq-first-failure-at`, `x-lerian-dlq-producer-id`) alongside the CloudEvents ce-* context attributes. DLQ publish failures surface on the `streaming_dlq_publish_failed_total` counter and are logged, not returned to the caller.
- **A consumer quarantines into its OWN DLQ** — `lerian.streaming.<consumer-app>.dlq`, derived from `ConsumerConfig.Source`, never from the record's topic. Consuming therefore does not widen an application's write grant, and a filling DLQ names the team that owns the fix.
- **Consumer quarantine adds three headers** the producer path does not have: `x-lerian-dlq-source-partition`, `x-lerian-dlq-source-offset` (the producer quarantines before any broker assigns them), and `x-lerian-dlq-cause-kind` — one of `codec` / `handler` / `source_mismatch` / `unhandled_key`. The cause kind also labels `streaming_consumer_dlq_total`. It exists because a DLQ where every entry carries the same message says only that *something* was terminal; those four kinds have four different owners and four different fixes. With consumer-owned DLQs the `source-topic` / `-partition` / `-offset` trio is load-bearing, not just forensic: the DLQ topic no longer implies where the record came from.
- **DLQ size rule.** A DLQ record is strictly LARGER than the record it quarantines (same payload + same headers + the forensic set), so **`.dlq` topics MUST be provisioned with `max.message.bytes` at or above their source topic's**. Library-side defences: `x-lerian-dlq-error-message` is capped at `dlqheader.MaxErrorMessageBytes` (4 KiB) with a truncation marker, and a size-driven publish failure (`dlqheader.IsSizeError`: `kerr.MessageTooLarge` or `contract.ErrPayloadTooLarge`) is retried ONCE with the payload omitted, marked by **`x-lerian-dlq-payload-omitted: "true"`** and **`x-lerian-dlq-payload-bytes`**. On a consumer quarantine the payload stays recoverable from the source topic via the origin coordinates; on the producer path it is genuinely gone. Both DLQ writers obey both rules.
- **Producer DLQ and consumer quarantine live on DIFFERENT `.dlq` topics** (the producer's own, and the consuming app's own) and are additionally distinguishable by headers: a consumer quarantine carries `x-lerian-dlq-source-partition` / `-source-offset` / `-cause-kind`; a producer DLQ copy has none of the three. **Replay rule:** replay a producer-written entry through the producer (the original publish never landed); replay a consumer-written entry by re-delivering to the CONSUMER (the record is on the source topic at the partition and offset the headers name, and the producer's copy is already durable — republishing it would duplicate the event).
- **Outbox replay trusts the persisted `Event.Source`** and does not cross-check it against the relaying producer's live `ce-source`. A row written by service A and drained by a relay configured for service B publishes to A's topic. In practice the relay runs in the owning service's own process, so the two agree; the residual risk is a mis-wired relay or a shared outbox table across services.

### Manifest and Introspection

- `BuildManifest(descriptor PublisherDescriptor, catalog Catalog, routes RouteTable) (ManifestDocument, error)` renders a JSON-serializable view of the catalog plus active route table for ops/contract introspection. The optional `Routes` field is populated when the route table has entries; an empty `RouteTable` produces a catalog-only document.
- `NewStreamingHandler(descriptor, catalog, opts ...HandlerOption) (http.Handler, error)` returns a stdlib `http.Handler` exposing the manifest. The handler pre-marshals the payload at construction; rebuild the handler if the catalog changes. Use `WithManifestRoutes(RouteTable)` to advertise the active route table in the manifest's `routes` section. **SECURITY:** the library does NOT enforce auth — callers MUST wrap the handler in their app's auth middleware before mounting publicly.
- `PublisherDescriptor` carries `ServiceName`, `Source` (renamed from v2's `SourceBase`; validated by `contract.ValidateSource` EXACTLY as given — deliberately NOT trimmed, because producer preflight validates untrimmed and a trim here would make `" lender "` publishable in the manifest and a hard failure at the first Emit), `RoutePath` (defaults `/streaming`), `OutboxSupported`, `AppVersion`, `LibVersion`, and `ProducerID` (random per process, surfaced for replica disambiguation in DLQ headers and span attributes).
- `ManifestDocument` advertises the application's single `topic` / `dlqTopic` pair at the DOCUMENT level. `ManifestEvent` has NO `topic` field — a definition has no topic of its own — and carries `eventKey` (`"<resourceType>.<eventType>"`) instead, alongside its schema version.
- `ManifestVersion` is a semver string (current `2.0.0`). Minor bumps are additive; major bumps remove or change a field.

### Health, Concurrency, Metrics

- `Healthy(ctx)` returns nil when ready; otherwise returns a `*HealthError` whose `State()` is one of `Healthy`, `Degraded` (broker unreachable but outbox viable), or `Down` (both unreachable). Health check bounds the broker Ping to 500ms.
- Concurrency: `*Producer`, `streamingtest.MockEmitter`, and `NoopEmitter` are all safe for concurrent use from any number of goroutines.
- Metrics: `streaming_emitted_total`, `streaming_emit_duration_ms`, `streaming_dlq_total`, `streaming_dlq_publish_failed_total`, `streaming_outbox_routed_total`, `streaming_outbox_replay_target_unknown_total`, `streaming_circuit_state`, `streaming_cb_recovery_liveness`. Consumer side: `streaming_consumer_dlq_total` (label `cause_kind`), `streaming_consumer_dlq_publish_failed_total`, `streaming_consumer_fetch_error_total`, `streaming_consumer_fetch_error_data_loss_total`, `streaming_consumer_system_event_total`, `streaming_consumer_partition_halted_total` (label `reason`: `sustained_transient` / `dlq_publish_failed` / `shutdown`), `streaming_consumer_unmatched_total` (label `event_key`, capped at 64 values + `other`). All registered via the `MetricsFactory` passed through `WithMetricsFactory`; nil factory degrades to a no-op recorder after a single WARN log at first Emit. **No `tenant_id` label on any metric** (cardinality discipline). Tenant identity lives on spans only.

### Runtime assertions (lib-observability/assert)

- The library enforces post-construction invariants via `github.com/LerianStudio/lib-observability/assert`. Internal invariant sites (e.g. nil client at `Close` time, nil outbox writer at a path that already gated on outbox availability) fire the observability trident (log + span event + `assertion_failed_total` metric) and still return the documented sentinel/error to the caller — public API contract is unchanged on the assertion-fires path.
- Assertions use `component="streaming"` and a per-call-site `operation` label. **No `tenant_id` label on any assertion metric** (same cardinality discipline as the `streaming_*` metrics). Tenant identity, when relevant, lives on span attributes only.
- lib-streaming does NOT own service bootstrap. Consuming services MUST call `assert.InitAssertionMetrics(metricsFactory)` once at bootstrap, after telemetry is initialized and alongside `runtime.InitPanicMetrics`. Without this call, the log and span-event layers still fire but the `assertion_failed_total` counter stays at zero, so dashboards will not alert on invariant spikes.
- Consuming services MUST also call `runtime.SetProductionMode(appCfg.Env == "production")` (or the equivalent service-owned environment flag) at bootstrap. Without it, panic value strings flow verbatim into log fields, span events, and ErrorReporter payloads — risking PII leakage — and stack traces stay un-truncated, bloating span attributes and risking OTel collector rejection. The CB recovery goroutine wraps `manager.GetState` via `runtime.SafeGoWithContextAndComponent`, so a panicking commons CB manager would feed exactly this leak path without production mode set.

## Coding rules

- Do not add `panic(...)` in production paths.
- Do not swallow errors; return or handle with context.
- Keep exported docs aligned with behavior.
- Reuse existing package patterns before introducing new abstractions.
- Avoid introducing high-cardinality telemetry labels by default.
- Use the structured log interface (`Log(ctx, level, msg, fields...)`) — do not add printf-style methods.
- Prefer `commons.GenerateUUIDv7()` over `uuid.New()` for time-ordered IDs (better B-tree locality on persisted rows).
